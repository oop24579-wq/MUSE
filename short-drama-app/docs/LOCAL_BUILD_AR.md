# بناء HERO DRAMA على جهازك — دليل خطوة بخطوة

الإصدار الحالي: 1.0.4+4 — اسم الحزمة: `com.shortdrama.watch`

## إيه الجاهز already (مش محتاج منك حاجة)

- الكود كامل ومختبَر: تحليل نظيف و101/101 اختبار ناجح، والـ CI على GitHub أخضر.
- ملف Firebase للأندرويد `google-services.json` موجود ومتطابق مع مشروعك
  `short-drama-c8029` ومع اسم الحزمة — مش محتاج تنزّله ولا تبدّله.
- إعدادات البناء مظبوطة: لو ملف التوقيع مش موجود، البناء بيوقّع تلقائيًا
  بمفتاح تجريبي (debug) عشان تقدر تثبّت وتجرّب على موبايلك فورًا.

## 1) المتطلبات على جهازك (مرة واحدة)

1. **Flutter SDK** (قناة stable) من https://docs.flutter.dev/get-started/install
   وبعده شغّل `flutter doctor` وعالج أي بند ناقص بيقوله.
2. **Android Studio** — بيوفّر Android SDK وأدوات البناء، وجواه JDK جاهز
   (فيه أداة `keytool` اللي هنحتاجها للتوقيع).
3. **Git** لسحب الكود.

## 2) هات الكود

```
git clone https://github.com/oop24579-wq/MUSE.git
cd MUSE\short-drama-app\short-drama-mobile
```

(لو عندك النسخة already: `git pull` من جوه مجلد MUSE.)

## 3) البناء التجريبي — خطوة واحدة

```
flutter pub get
flutter build apk --release
```

الناتج هتلاقيه هنا:

```
build\app\outputs\flutter-apk\app-release.apk
```

انقله على موبايلك وثبّته وجرب براحتك. البناء ده موقّع بالمفتاح التجريبي —
ممتاز للتجربة، بس **مش** صالح للرفع على Google Play.

## 4) البناء الموقّع للنشر على المتجر (مرة واحدة للإعداد)

### أ) اعمل مفتاح التوقيع بتاعك

من أي موجّه أوامر (الأداة موجودة مع JDK اللي مع Android Studio):

```
keytool -genkey -v -keystore herodrama-release.jks -keyalg RSA -keysize 2048 -validity 10000 -alias herodrama
```

هيسألك عن كلمة سر للمخزن وكلمة سر للمفتاح وبيانات بسيطة.
**احفظ ملف الـ jks وكلمتين السر في مكان آمن** — لو ضاعوا مش هتعرف
تحدّث التطبيق على المتجر أبدًا بعد كده.

### ب) حط الملفات في أماكنها

1. انقل `herodrama-release.jks` لجوه مجلد `android\` في المشروع.
2. في نفس المجلد هتلاقي `key.properties.example` — اعمل منه نسخة باسم
   `key.properties` بالضبط، وعدّل القيم الأربعة اللي جواه بكلمات السر
   بتاعتك (الملف مشروح سطر بسطر).

الملفين دول مستثنيين من Git already (في .gitignore) — **ما يترفعوش
على GitHub ولا يتبعتوا لحد أبدًا**.

### ج) ابنِ بنفس الأمر

```
flutter build apk --release
```

طالما `key.properties` موجود، البناء بيوقّع بمفتاحك تلقائيًا، والناتج
في نفس المكان اللي فوق — وده الصالح للنشر.

> للنشر على Google Play تحديدًا، المتجر بيفضّل صيغة App Bundle:
> `flutter build appbundle --release`
> والناتج: `build\app\outputs\bundle\release\app-release.aab`

## 5) Firebase — مهمتين من جهتك (مش للبناء، لتشغيل الخدمات)

1. **تقييد أو تدوير مفتاح الـ API المكشوف:** ملف google-services.json
   اترفع على GitHub قبل كده ووصلك تنبيه من GitHub عنه. من Google Cloud
   Console قيّد المفتاح على تطبيق الأندرويد بتاعك، أو اعمل مفتاح جديد
   وبدّله في Firebase — دي خطوة أمان مهمة قبل أي إطلاق عام.
2. **عنوان الباك إند (Remote Config):** التطبيق بياخد عنوان السيرفر من
   Firebase Remote Config في مشروع `short-drama-c8029`، من باراميتر
   اسمه `api_base_url`. حط فيه رابط الباك إند العام بتاعك وانشر
   (Publish). من غيره التطبيق هيفتح بس مش هيوصل لأي محتوى.

## 6) الباك إند — لازم يكون شغال على رابط عام

الـ APK لوحده مش كفاية: التطبيق بيكلم الباك إند اللي في
`short-drama-app\backend`. شغّله على سيرفر/استضافة برابط عام (HTTPS)،
وظبط ملف `.env` بتاعه (القالب الجاهز `backend\.env.example` مشروح):

- `FIREBASE_PROJECT_ID=short-drama-c8029` — لتفعيل التحقق الحقيقي من
  تسجيل الدخول (من غيره الباك إند بيشتغل في وضع تجريبي غير آمن للنشر).
- `REVENUECAT_WEBHOOK_SECRET` — سرّ بتولّده انت وبتحطه هو نفسه في
  لوحة RevenueCat عند تسجيل الـ webhook، عشان عمليات الشراء تتسجل
  صح (من غيره الـ webhook مرفوض في وضع الإنتاج).
